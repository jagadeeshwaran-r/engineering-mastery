> Shared state and system behavior

## Why this category exists

Performance and concurrency problems are subtle: correctness can fail under interleaving, while measurements can be misleading. This shelf pairs Java concurrency with systems grounding.

## What you'll learn

- Reason about thread safety
- Distinguish latency, throughput and contention
- Design and interpret simple measurements

## Books and why they belong here

| Book / guide | Role | Why it is included |
|---|---|---|
| [Computer Systems: A Programmer's Perspective](../reading-guides/computer-systems-a-programmers-perspective.md) | Systems foundations | Serves as a modernized systems reference for performance-oriented reading. |
| [Java Concurrency in Practice](../reading-guides/java-concurrency-in-practice.md) | Java concurrency | Builds disciplined reasoning about Java thread safety and shared state. |
| [Computer Systems: A Programmer's Perspective](../reading-guides/computer-systems-a-programmers-perspective.md) | Edition reference | Preserves an older edition for comparison rather than creating a separate reading requirement. |

> **Edition note:** *Computer Systems: A Programmer's Perspective* appears in more than one folder/edition. It is one work with multiple references, not multiple required books. See the [single consolidated guide](../reading-guides/computer-systems-a-programmers-perspective.md).

## Suggested reading order

Prioritize **Java Concurrency in Practice** for Java concurrency. Use a single edition of **Computer Systems: A Programmer's Perspective** for memory and performance background; the second and third editions are alternatives, not two independent subjects.

## A practical outcome

Demonstrate a race condition, fix it, and describe how you validated the result.
