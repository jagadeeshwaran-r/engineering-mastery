> Maintainable engineering

## Why this category exists

Production engineering is about software that teams can understand, test and change. These texts offer complementary perspectives on craftsmanship and architectural decisions.

## What you'll learn

- Make code easier to read and change
- Separate responsibilities and dependencies
- Evaluate design advice rather than apply it mechanically

## Books and why they belong here

| Book / guide | Role | Why it is included |
|---|---|---|
| [Clean Architecture](../reading-guides/clean-architecture.md) | Architecture | Frames software boundaries, dependencies and architectural decision-making. |
| [Clean Code](../reading-guides/clean-code.md) | Craft | Prompts critical reflection on naming, structure and maintainability. |
| [The Pragmatic Programmer](../reading-guides/the-pragmatic-programmer.md) | Professional practice | Encourages practical judgment, continuous learning and better engineering habits. |

## Suggested reading order

Read **The Pragmatic Programmer** for working habits, **Clean Code** for code-level discussion, and **Clean Architecture** for system boundaries. Treat all prescriptive advice as context-dependent.

## A practical outcome

Refactor a Java module with tests, explain what changed, and list the trade-offs.
