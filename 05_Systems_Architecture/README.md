> How software works at scale

## Why this category exists

Architecture connects code to hardware, databases and distributed behavior. Understanding both a single machine and a larger data system enables more informed designs.

## What you'll learn

- Reason about memory and program behavior
- Compare data-system trade-offs
- Explain architecture decisions and failure modes

## Books and why they belong here

| Book / guide | Role | Why it is included |
|---|---|---|
| [Designing Data-Intensive Applications](../reading-guides/designing-data-intensive-applications.md) | Architecture | Connects database and distributed-system choices to real engineering trade-offs. |
| [Computer Systems: A Programmer's Perspective](../reading-guides/computer-systems-a-programmers-perspective.md) | Systems foundations | Explains the machine-level behavior underlying software performance and correctness. |

> **Edition note:** *Computer Systems: A Programmer's Perspective* appears in more than one folder/edition. It is one work with multiple references, not multiple required books. See the [single consolidated guide](../reading-guides/computer-systems-a-programmers-perspective.md).

## Suggested reading order

Use **Computer Systems: A Programmer's Perspective** for lower-level foundations and **Designing Data-Intensive Applications** for the data-system perspective.

## A practical outcome

Draw a request path through an application and document one scalability or consistency trade-off.
